About URL Encoding & Percent-Encoding

URL encoding—formally specified as percent-encoding in RFC 3986—replaces unsafe or reserved characters with a % symbol followed by two hexadecimal digits representing the character's UTF-8 byte value. Because URLs can only be transmitted over the Internet using a strict subset of ASCII characters, symbols such as spaces, ampersands (&), question marks (?), and international Unicode characters must be encoded so they don't break query strings or routing paths.

The Filediter URL Encoder / Decoder supports both component-level encoding (encodeURIComponent) for query parameter values and full-URI encoding (encodeURI) when you want to keep protocol and path delimiters intact.

🔗 Component vs. Full URL

Keep "Encode all characters" enabled when encoding query values (so & and = become %26 and %3D). Uncheck it when encoding a complete URL while preserving https:// and slashes.

➕ Form Query Strings

HTML forms and search engines often replace spaces with + instead of %20. In Decode Mode, our tool automatically converts + back into spaces when that option is checked.

🛡️ 100% Client-Side Privacy

All encoding and decoding executes directly inside your browser. API keys, OAuth redirect URLs, webhook payloads, and query parameters never leave your device.

Common percent-encoding examples

Spaces & Formatting

Standard percent-encoding converts a space to %20, while URL form encoding uses +. Line breaks encode to %0A (LF) or %0D%0A (CRLF).

Reserved Delimiters

Characters that structure URLs have dedicated hex codes: ? → %3F, & → %26, = → %3D, # → %23, and / → %2F.

UTF-8 International Text

Non-ASCII characters and emojis are converted into multi-byte UTF-8 sequences (for example, € encodes to %E2%82%AC).

Frequently asked questions

What is the difference between encodeURIComponent and encodeURI?

encodeURIComponent encodes all special characters including reserved URI delimiters (: / ? # & = +), making it ideal for individual query parameter values. encodeURI leaves full URL structure characters intact so a complete web address stays clickable.

How are plus (+) signs handled when decoding?

In application/x-www-form-urlencoded query strings, spaces are often encoded as + instead of %20. Enable the "Treat + as space when decoding" option to convert + characters back into spaces before percent-decoding.

Why did I get an "Invalid or malformed percent-encoded string" error?

This happens when a string contains a literal % sign that is not followed by two valid hexadecimal digits (0-9, A-F), or contains an incomplete UTF-8 byte sequence.

Are my URLs or API payloads sent to a server?

No. All URL encoding and decoding happens locally inside your browser using native JavaScript functions. Your text, tokens, and query strings never leave your device.
